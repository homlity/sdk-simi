01 Qué es y para qué sirve

SIMI es un CRM inmobiliario usado por inmobiliarias y constructoras para administrar su inventario, sus asesores y sus sedes. Expone ese inventario mediante un API HTTP autenticado con un token por inmobiliaria.

Ese API devuelve JSON crudo, con nombres de campo inconsistentes entre endpoints (Codigo_Inmueble frente a idInm, banios frente a banos, Venta frente a ValorVenta) y precios guardados como texto con símbolos y puntos. Este SDK existe para que nunca tengas que tocar ese JSON.

Consumiendo el API directoCon el SDK
Armar URLs tipo /filtroInmueble/ciudad/5/total/12$api->getInmuebles(["ciudad"=>5,"total"=>12])
curl + json_decode + validar status en cada llamadaObjetos Response* con isSuccess()
Leer $json["Inmuebles"][0]["Codigo_Inmueble"]$inmueble->identificacion()
Limpiar "$ 350.000.000" a punta de regex$inmueble->valorVenta()
Descubrir los filtros válidos a base de erroresLista blanca: un filtro inválido lanza excepción de inmediato
Reimplementar la paginación en cada proyectoPaginadorInmueblePreview + PaginatorHTML

Casos de uso típicos

Portales inmobiliarios

Listados con filtros, ficha de detalle, mapa, galería, video y recorridos 360.

Home y landings

Carrusel de inmuebles destacados con precio, foto y ubicación reales.

Buscadores

Selects encadenados departamento → ciudad → barrio, tipos y gestiones.

Equipo comercial

Listado paginado de asesores con foto, celular y correo.

Feeds y sincronizaciones

Exportar el inventario hacia portales externos u otros sistemas.

Widgets de WordPress

Shortcodes alimentados con inventario real y caché por transient.

Instalar con Composer

terminal
composer require homlity/sdk-simi

El nombre del paquete es homlity/sdk-simi y el repositorio es github.com/homlity/sdk-simi.

Migración desde codwelt/sdk-simi

El paquete se publicaba antes bajo el vendor codwelt. El vendor y el namespace ahora son homlity, y ese es un cambio incompatible hacia atrás: todo el código que ya use el SDK debe actualizar sus importaciones. Ninguna clase, método ni firma cambió — solo el namespace.

antes → después
- composer require codwelt/sdk-simi
+ composer require homlity/sdk-simi

- use Codwelt\SIMI\SDK\Domain\Providers\ApiServiceProvider;
+ use Homlity\SIMI\SDK\Domain\Providers\ApiServiceProvider;

Un solo comando actualiza todas las referencias de tu proyecto, y después basta con composer dump-autoload:

terminal
grep -rl 'Codwelt\\SIMI\\SDK' app/ config/ resources/ \
  | xargs sed -i '' 's/Codwelt\\SIMI\\SDK/Homlity\\SIMI\\SDK/g'   # macOS

composer dump-autoload
Corresponde una versión mayor

Cambiar el namespace rompe la compatibilidad hacia atrás, así que la versión indicada es v3.0.0. Publica ese tag antes de usar la restricción ^3.0; mientras no exista, apunta a dev-master.

Instalar desde el repositorio

Si trabajas contra un fork, una rama de desarrollo o un Packagist privado, declara el repositorio VCS en tu composer.json:

composer.json
{
  "repositories": [
    { "type": "vcs", "url": "https://github.com/homlity/sdk-simi.git" }
  ],
  "require": {
    "homlity/sdk-simi": "^3.0"
  }
}

Para fijar una versión exacta usa cualquiera de los tags publicados: v2.5.7, v2.5.6, v2.5.5…

Autoload

El paquete usa PSR-4: el namespace Homlity\SIMI\SDK\ apunta a src/. Basta con incluir el autoloader de Composer.

php
require __DIR__ . '/vendor/autoload.php';

03 El token de SIMI

Todas las peticiones se autentican con un único token que SIMI entrega a cada inmobiliaria. El SDK lo valida antes de permitir cualquier llamada, contra esta expresión regular:

validación del token
/^([A-Za-z0-9]{40,50})-([0-9]+)$/

Es decir: entre 40 y 50 caracteres alfanuméricos, un guion, y un número que identifica la inmobiliaria o sede. Si el token no cumple el formato, setTokenProvider() lanza Exception: El token es invalido.

Cómo viaja en cada petición

DestinoMecanismo
http://simi-api.com/ApiSimiweb/response/HTTP Basic Auth con usuario vacío y el token como contraseña (CURLOPT_USERPWD = ":$token")
https://api.simicrm.app/crm/
(solo getEstadoInmueble)		Cabeceras token: <token> y Accept: application/vnd.apisimi.v3+json
Nunca lo publiques

El token da acceso completo al inventario de la inmobiliaria. No lo escribas en el código fuente ni lo subas al repositorio: cárgalo desde variables de entorno. Para eso existe la interfaz TokenServiceProviderRespository, que recibe el SDK en lugar del token en crudo.

04 Primeros pasos

Paso 1 — Implementa tu proveedor de token

El SDK no recibe el token: recibe un objeto que sabe dónde encontrarlo. Así puedes leerlo del entorno, de la base de datos, de un gestor de secretos o de la configuración multi-sitio sin tocar el SDK.

TokenSimiProvider.php
<?php

use Homlity\SIMI\SDK\Domain\Providers\TokenServiceProviderRespository;

class TokenSimiProvider implements TokenServiceProviderRespository
{
    public function getToken(): string
    {
        return getenv('SIMI_TOKEN');
    }
}

Paso 2 — Construye el API

php
<?php
require __DIR__ . '/vendor/autoload.php';

use Homlity\SIMI\SDK\Domain\Providers\ApiServiceProvider;

$provider = ApiServiceProvider::build();
$provider->setTokenProvider(new TokenSimiProvider());   // valida el token aquí

$api = $provider->getAPi();                             // instancia de ApiFachada
Atajo

Si no necesitas el proveedor, instancia la fachada directamente con new ApiFachada($token). Esa vía es la recomendada dentro de un contenedor de dependencias, pero no valida el formato del token.

Paso 3 — Consulta inmuebles

php
$resultado = $api->getInmuebles([
    'ciudad'  => 5,
    'tipOper' => 1,   // gestión: venta / arriendo
    'total'   => 12,  // registros por página
    'limite'  => 1,   // página
]);

$inmuebles = $resultado['inmuebles'];   // InmueblePreview[]
$paginador = $resultado['paginador'];   // PaginadorInmueblePreview|null

foreach ($inmuebles as $inmueble) {
    echo $inmueble->nombre();           // "Apartamento - El Poblado, Medellín"
    echo $inmueble->identificacion();   // "503-4848"
    echo $inmueble->valorVenta();       // "350.000.000"
    echo $inmueble->fotoPortada();      // URL de la foto principal
}

Paso 4 — Ficha de detalle

php
$detalle = $api->getDetalleInmueble('503-4848');

if ($detalle === null) {          // no existe, o el API no respondió
    http_response_code(404);
    exit('Inmueble no disponible');
}

echo $detalle->tipoInmueble();     // "APARTAMENTO"
echo $detalle->areaConstruida();   // "85"

foreach ($detalle->fotos() as $foto) {
    echo '<img src="' . htmlspecialchars($foto['foto']) . '">';
}

$asesor = $detalle->asesor();
if ($asesor !== null) {
    echo $asesor->nombre() . ' - ' . $asesor->celular();
}

05 Arquitectura

El paquete separa por capas al estilo de una arquitectura hexagonal: el dominio define contratos, la infraestructura habla HTTP y mapea JSON, y la aplicación ofrece casos de uso ya resueltos.

estructura de src/
src/
├── Domain/                      ← contratos y puertos (lo estable)
│   ├── API/ApiFachadaRepository.php          contrato del API
│   ├── API/ApiModelRepositoryFachada.php     variante con modelos de dominio
│   ├── ModelRepository/Inmueble.php
│   └── Providers/
│       ├── ApiServiceProviderRepository.php  fábrica + validación del token
│       ├── ApiServiceProvider.php
│       ├── ApiModelRepositoryServiceProvider.php
│       └── TokenServiceProviderRespository.php  ← la implementas tú
│
├── InfraStructure/              ← HTTP y mapeo del JSON
│   ├── API/ApiFachada.php       los métodos que usas
│   ├── Requests/                una clase por endpoint + HttpClient (cURL)
│   ├── Responses/               isSuccess() / getBody()
│   └── Modelos/                 InmueblePreview, InmuebleDetail, Ciudad…
│
├── Application/                 ← casos de uso listos
│   ├── ObtenedorInmueblesSimilaresService.php
│   ├── ObtenedorUrlFichaInmuebleService.php
│   └── Models/PaginatorHTML.php
│
└── Helpers/
Por qué te importa

Tipa tu código contra la abstracción ApiFachadaRepository, no contra ApiFachada. Eso te permite inyectar un doble de prueba o un decorador con caché sin tocar nada más — y es exactamente lo que hacen los servicios de Application/, que reciben la abstracción por constructor.

Catálogos como JSON

Departamento, Ciudad, Barrio, TipoInmueble y GestionInmueble implementan JsonSerializable, así que puedes devolverlos tal cual desde un endpoint propio para alimentar tu frontend.

php
header('Content-Type: application/json');
echo json_encode($api->getCiudades(5));
// [{"id":"1","nombre":"MEDELLIN"}, …]

Tipos e inventario

php
foreach ($api->getTiposInmueble() as $tipo) {
    printf("%s (%d)\n", $tipo->nombre(), $tipo->totalInmuebles());
    // Apartamento (124)  ← ideal para menús y facetas
}

foreach ($api->getGestionesInmueble() as $gestion) {
    // el id() de la gestión es el valor del filtro tipOper
    echo $gestion->id() . ' → ' . $gestion->nombre();
}
getEstadoInmueble usa otro API

Ese método consulta https://api.simicrm.app/crm/ con la versión v3 y autenticación por cabecera, no el API web de SIMI. Si tu token no está habilitado allí, devolverá un array vacío aunque el resto del SDK funcione con normalidad.

07 Filtros disponibles

Los filtros se validan contra una lista blanca: cualquier clave fuera de ella lanza Exception: Filtro (x) no esta permitido en APISIMI. Si saneas tus $_GET antes de llamar al SDK, evitas ese error por completo.

getInmuebles()

departamentoId de departamento, de getDepartamentos()5
ciudadId de ciudad, de getCiudades()1
zonaId de zona12
barrioId de barrio, de getBarrios()320
tipoInmId de tipo de inmueble1
tipOperId de gestión u operación2
areamin / areamaxRango de área construida en m²50 / 180
valmin / valmaxRango de precio, sin puntos ni símbolos200000000

Los otros dos listados

MétodoFiltros permitidosValores por defecto
getInmueblesDestacados()limite, total—
getAsesores()limite, cantidad, asesorcantidad = 30, limite = 1

Saneado recomendado

php
$permitidos = ['departamento','ciudad','zona','barrio','tipoInm','tipOper',
               'areamin','areamax','valmin','valmax','banios','garajes','alcobas'];

$filtros = array_intersect_key($_GET, array_flip($permitidos));
$filtros = array_filter($filtros, fn($v) => $v !== '' && $v !== null);

$filtros['total']  = 12;
$filtros['limite'] = max(1, (int) ($_GET['page'] ?? 1));

$resultado = $api->getInmuebles($filtros);
Los ceros se pierden

getInmuebles() descarta internamente los filtros con valor vacío usando !empty(), así que ['garajes' => 0] nunca llega al API. Para el caso «sin garaje» tendrás que filtrar del lado de tu aplicación.

09 Servicios y paginación

La carpeta Application/ trae casos de uso que ya resuelven problemas frecuentes de un portal inmobiliario.

ObtenedorInmueblesSimilaresService

Devuelve inmuebles parecidos a uno dado — misma zona, mismo tipo, misma gestión — descartando el original. Es el bloque «También te puede interesar» de la ficha.

php
use Homlity\SIMI\SDK\Application\ObtenedorInmueblesSimilaresService;

$servicio = new ObtenedorInmueblesSimilaresService($api);

// A partir del código (consulta el detalle internamente)
$similares = $servicio->obtenerConCodigo('503-4848');

// O con el detalle ya cargado: evitas una petición extra
$similares = $servicio->obtener($detalle, 5);   // devuelve hasta 4
Pide uno más

obtener($detalle, $cantidad) solicita $cantidad inmuebles al API y devuelve $cantidad - 1, porque reserva un espacio para descartar el inmueble original. Si quieres mostrar cuatro, pide cinco.

ObtenedorUrlFichaInmuebleService

php
$url = (new ObtenedorUrlFichaInmuebleService())->getUrl($inmueblePreview);
// https://simicrm.app/mcomercialweb/fichas_tecnicas/fichatec3.php?reg=503-4848

Paginación

getInmuebles() y getInmueblesDestacados() devuelven un PaginadorInmueblePreview; getAsesores() devuelve un PaginadorAsesores. Ambos son null cuando la petición no fue exitosa, así que verifícalos siempre antes de usarlos.

PaginadorInmueblePreviewPaginadorAsesoresDevuelve

totalPorPagina()totalPorPagina()Registros por página
numeroPaginaInicio() / numeroPaginaFin()IgualesRango de la página

PaginatorHTML

Genera el HTML de la paginación, con clases compatibles con Bootstrap, o te entrega las páginas como array si prefieres maquetarlo tú.

php
use Homlity\SIMI\SDK\Application\Models\PaginatorHTML;

$p = $resultado['paginador'];

if ($p !== null && $p->totalPorPagina() > 0) {
    $html = new PaginatorHTML(
        $p->totalInmuebles(),               // total de registros
        $p->totalPorPagina(),               // registros por página
        $p->paginaActual(),                 // página actual
        '/inmuebles?page=__PAGENUMBER__'    // patrón de URL
    );
    $html->setMaxPagesToShow(7);

    echo $html->toHtml();

    // o maquetas tú:
    foreach ($html->getPages() as $page) {
        // ['num' => 3, 'url' => '/inmuebles?page=3', 'isCurrent' => false]
    }
}

10 Laravel y WordPress

Laravel

Registra la abstracción en el contenedor una sola vez y luego inyéctala donde la necesites.

app/Providers/SimiServiceProvider.php
<?php
namespace App\Providers;

use Illuminate\Support\ServiceProvider;
use Homlity\SIMI\SDK\Domain\API\ApiFachadaRepository;
use Homlity\SIMI\SDK\InfraStructure\API\ApiFachada;

class SimiServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->singleton(ApiFachadaRepository::class, function () {
            return new ApiFachada((string) config('simi.token'));
        });
    }
}
app/Http/Controllers/InmuebleController.php
public function __construct(private ApiFachadaRepository $simi) {}

public function index(Request $request)
{
    $filtros = array_filter($request->only([
        'ciudad', 'barrio', 'tipoInm', 'tipOper', 'valmin', 'valmax', 'alcobas',
    ]));
    $filtros['total']  = 12;
    $filtros['limite'] = max(1, (int) $request->query('page', 1));

    $resultado = cache()->remember(
        'simi:inmuebles:' . md5(serialize($filtros)),
        now()->addMinutes(10),
        fn () => $this->simi->getInmuebles($filtros)
    );

    return view('inmuebles.index', $resultado);
}

public function show(string $codigo)
{
    $detalle = $this->simi->getDetalleInmueble($codigo);
    abort_if($detalle === null, 404);

    return view('inmuebles.show', ['inmueble' => $detalle]);
}
Por qué no ApiServiceProvider::build()

Dentro de un contenedor conviene instanciar ApiFachada directamente para no depender del singleton estático del SDK (ver advertencia 1). Si quieres conservar la validación del formato del token, llama a setTokenProvider() una única vez en el register().

WordPress

Un shortcode [simi_destacados total="6"] con caché por transient:

simi-inmuebles.php
require_once __DIR__ . '/vendor/autoload.php';

use Homlity\SIMI\SDK\InfraStructure\API\ApiFachada;

function simi_api() {
    static $api = null;
    if ($api === null) {
        $api = new ApiFachada(SIMI_TOKEN);   // definido en wp-config.php
    }
    return $api;
}

function simi_destacados_shortcode($atts) {
    $atts = shortcode_atts(['total' => 6], $atts);
    $key  = 'simi_destacados_' . (int) $atts['total'];

    $inmuebles = get_transient($key);
    if ($inmuebles === false) {
        try {
            $inmuebles = simi_api()
                ->getInmueblesDestacados(['total' => (int) $atts['total']])['inmuebles'];
        } catch (\Exception $e) {
            error_log('[SIMI] ' . $e->getMessage());
            return '';
        }
        set_transient($key, $inmuebles, 15 * MINUTE_IN_SECONDS);
    }

    ob_start(); ?>
    <div class="simi-grid">
      <?php foreach ($inmuebles as $i): ?>
        <article class="simi-card">
          <img src="<?php echo esc_url($i->fotoPortada()); ?>" loading="lazy" alt="">
          <h3><?php echo esc_html($i->nombre()); ?></h3>
          <p><?php echo $i->enArriendo()
                ? '$ ' . esc_html($i->valorArriendo()) . ' /mes'
                : '$ ' . esc_html($i->valorVenta()); ?></p>
        </article>
      <?php endforeach; ?>
    </div>

11 Rendimiento y caché

El API de SIMI es la parte lenta de cualquier página que lo consuma, y el SDK no define timeouts de cURL. Cachea siempre.

Como los servicios del SDK dependen de la abstracción ApiFachadaRepository, puedes envolver la fachada real en un decorador con caché sin cambiar nada más de tu código.

ApiSimiConCache.php
use Homlity\SIMI\SDK\Domain\API\ApiFachadaRepository;

class ApiSimiConCache extends ApiFachadaRepository
{
    public function __construct(
        private ApiFachadaRepository $inner,
        private \Psr\SimpleCache\CacheInterface $cache
    ) {
        parent::__construct($inner->getToken());
    }

    private function recordar(string $clave, callable $fn, int $ttl)
    {
        $clave = 'simi.' . md5($clave);
        $hit   = $this->cache->get($clave);
        if ($hit !== null) {
            return $hit;
        }
        $valor = $fn();
        $this->cache->set($clave, $valor, $ttl);
        return $valor;
    }

    public function getInmuebles(array $filters = [])
    {
        return $this->recordar('inmuebles' . serialize($filters),
            fn () => $this->inner->getInmuebles($filters), 600);
    }

    public function getDetalleInmueble($codigo)
    {
        return $this->recordar('detalle' . $codigo,
            fn () => $this->inner->getDetalleInmueble($codigo), 1800);
    }

    // … el resto de métodos abstractos, delegando igual
}

El SDK usa dos mecanismos distintos, y conviene tener claro cuál aplica en cada caso.

Excepciones: errores de configuración o de código

Respuestas vacías: fallos del API

Si el API responde con error, no responde, o devuelve un cuerpo inesperado, no hay excepción: recibes listas vacías o null. Un listado vacío puede significar «sin resultados» o «el API está caído», y desde tu código se ven igual.

patrón recomendado
try {
    $resultado = $api->getInmuebles($filtros);
} catch (\Exception $e) {
    error_log('[SIMI] ' . $e->getMessage());
    $resultado = ['inmuebles' => [], 'paginador' => null];
}

if (empty($resultado['inmuebles'])) {
    // muestra un estado vacío, no un error técnico
}

13 Advertencias del SDK

Particularidades reales del código fuente. Conocerlas ahorra horas de depuración.

  1. build() es un singleton compartido entre proveedores. La instancia se guarda en una propiedad estática de la clase padre, así que si en el mismo proceso llamas primero a ApiServiceProvider::build() y luego a ApiModelRepositoryServiceProvider::build(), la segunda llamada devuelve la primera instancia. Si necesitas ambas variantes, instancia las fachadas directamente. 
    $api      = new ApiFachada($token);
$apiModel = new ApiModelRepositoryFachada($token);
  2. Los filtros con valor 0 se descartan. getInmuebles() filtra con !empty($value): ['garajes' => 0] nunca llega al API.
  3. idTipoInmueble() es protected en InmueblePreview. Solo es público en InmuebleDetail; llamarlo sobre un preview desde fuera de la clase produce un Error de PHP.
  4. fotoPortada() del detalle asume que hay fotos. Accede a fotos()[0]["foto"] sin validar. Comprueba el array antes de usarlo.
  5. Domain\ModelRepository\Inmueble::valorArriendo() devuelve el valor de venta. Es un defecto conocido de esa clase auxiliar: usa valorArriendo() de InmueblePreview o InmuebleDetail.
  6. caracterisitcasInternas() está escrito con errata — caracterisitcas, no caracteristicas. Se mantiene así por compatibilidad hacia atrás.
  7. La URL base por defecto es HTTP, no HTTPS (http://simi-api.com/ApiSimiweb/response/). Solo getEstadoInmueble() usa https://api.simicrm.app/crm/.
  8. cURL no define timeouts. Una caída del API puede colgar tu petición: envuelve las llamadas en tu propia capa con caché, o resuélvelas en segundo plano.
  9. getEstadoInmueble() habla con otro API y otra versión. Que funcionen los demás métodos no garantiza que este también.
  10. Los métodos de catálogo no verifican isSuccess() antes de iterar. getDepartamentos() recorre la respuesta directamente; si el API falla puede propagarse un aviso de PHP. Envuélvelos en try/catch en producción.
